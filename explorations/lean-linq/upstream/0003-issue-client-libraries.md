The lakefile looks up libsqlite3, libpq, libsybdb and libmysqlclient when Lake loads it, and stops with an error if any of them is missing. A project that only uses Postgres, for example, has to install FreeTDS and the MySQL client before Lake will load lean-linq. The link settings also stay inside lean-linq's package. A program in another package that imports `LeanLinq.Driver.Postgres` fails to link with undefined `PQ*` symbols until that package adds libpq itself.

I tried one way around both on Linux. Each driver gets its own `lean_lib`, which names its client library in `moreLinkObjs` through a `target` that finds the library only when something links against it. Lake collects `moreLinkObjs` from every library a program imports, including libraries in other packages. With that layout, a program in another package that imports only the Postgres driver linked libpq alone. It needed no link settings of its own. Lake loaded lean-linq with FreeTDS uninstalled, and the Postgres sweep still passed.

One part doesn't carry over. Some system libraries, such as SQLite on Ubuntu 24.04, use newer glibc symbols than Lean's own glibc and need `-Wl,--allow-shlib-undefined`. Lake doesn't pass link arguments on to other packages. Programs that use those drivers would still add that flag themselves.

Would a change along those lines suit you? I'd keep the macOS lookups as they are, and I'm glad to shape it however you prefer.
