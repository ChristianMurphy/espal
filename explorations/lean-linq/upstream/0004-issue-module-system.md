Lean's module system has been stable since Lean 4.27.0, and a file that starts with `module` can only import other modules. Projects that adopt it can't import lean-linq yet, since Lean reports `cannot import non-module LeanLinq from module`. Files outside the module system can still import modules, so moving lean-linq over wouldn't change anything for its current users.

I tried a conversion on Lean 4.35.0 to see how far it gets. Each file got a `module` header, public imports and an exposed public section. The library turned on the `backward.privateInPublic` porting option, and the six elaborators and macros, plus four helpers they call, became `meta`. With that, every module up to `Theorems.lean` builds. Its proofs rewrite with `List.filterAuxM`, whose body Lean's core doesn't expose to modules, so they'd need another route. `Db.lean` and the root module come after it, so I couldn't check them.

Is moving to the module system something you'd want for lean-linq? If so, I could open a draft pull request with the conversion so far and work through `Theorems.lean` with you.
